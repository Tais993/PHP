== Introduction

=== Context:

As an ITer, photographer, videographer and other tasks I’m constantly spending time figuring out what to do next and what has to be done. Tasks are maintained across multiple applications and systems. This sometimes results in deadlines being forgotten, or incorrectly remembered.

Additionally, I’d like to follow the news more proactively. Existing news sites contain a lot of information, and requires opening multiple before getting a good overview.

PHP is an application, a homepage being focused primarily on task management. This project will have functionalities such as tasks, Kanban boards, views, deadlines, users and eventually other non-task management related features.

=== Purpose of this document:

The purpose of this document is to showcase the implementation of the decided design and architecture of the project.

It will cover the front-end, the interaction, and follow it fully to the end with the database connection. 

The goal of this is to show-case how the application runs, in practice and not in theory.

== Frontend

=== User action

The user has to open a board, and click on either the “New task” or “+ Add task” button.

For the main example, we will visit `/boards/1` and click on "Add task" at the top right.

image::task-board.png[Kanban board with a New task button and an Add task button in each column]

The follow information will be submitted:
[cols="1,2,2",options="header"]
|===
|Field |User input |Submitted value
|Title |`"  Prepare sprint demo  "` |`"Prepare sprint demo"`
|Description |`"  Demonstrate task creation  "` |`"Demonstrate task creation"`
|Board |Selected through the URL |`1`
|Status |Top-level button supplies none |`null`
|===

Which results in the following (local) HTTP request:

[source,http]

Content-Type: application/json

[source,properties]

----

with:

[source,java]

@PostMapping

This results in the external route becoming `POST /api/tasks`

As CORS is configured, browser requests are only allowed from configured origins. This does not authenticate or prevent direct calls to the API.

In the development setup, localhost is allowed. Outside of that, the `FRONTEND_ORIGINS` environmental variable has to be configured.


Spring MVC reads the request body, it reads the JSON and constructs a `CreateTaskRequest`

[source,java]
----
public record CreateTaskRequest(
        String title,
        Long boardId,
        String description,
        Long statusId
) {}
----

This contains no validation, there are absolutely no constraints. In case a malformed JSON is received, Spring throws an exception. This exception is handled and results in a 400 error response.

=== Application service and business rules

Source: {src}/backend/application/src/main/java/nl/tijsbeek/services/TaskServiceImpl.java[`backend/application/src/main/java/nl/tijsbeek/services/TaskServiceImpl.java`].

`createTask` is transactional:

[source,java]
----
@Transactional
@Override
public Task createTask(
        String title,
        Long boardId,
        String description,
        Long statusId
) {
    // ...
}
----

The execution order is:

. Load the board through `BoardRepository`.
. Reject a missing board with `InvalidTaskReferenceException`.
. If `statusId` is non-null, find it in that board's status list.
. Reject a missing or foreign-board status.
. Construct the new domain task.
. Save it through `TaskRepository`.

Construction is:

[source,java]
----
Task task = new Task(
        null, selectedBoardId, title, description, null, status
);
----

At this point:

[cols="1,3",options="header"]
|===
|Value |State
|ID |`null`, because the database has not generated it
|Board ID |`1L`, after applying the default if needed
|Title and description |Unchanged from the controller
|Creation timestamp |`null`
|Status |`null`, or a resolved `BoardStatus`
|===

Sources:

The application interface exposes domain types:

[source,java]
----
Task save(Task task);
Optional<Task> findById(long id);
----

It does not expose anything related to JPA, Spring Data or the `EntityManager`.


`TaskRepositoryImpl` implements that interface. It is an infrastructure implementation marked `@Repository`.

`TaskJpaRepository` is a different interface:

[source,java]
----
public interface TaskJpaRepository
        extends JpaRepository<TaskJPA, Long>, TaskViewQueries {
}
----

The JPARepository implementation is provided by the framework, which Spring Data provides in runtime.

Dependency injection is enabled through the `@SpringBootApplication` annotation on `Main`.

Spring discovers both `TaskServiceImpl` and `TaskRepositoryImpl` through component scanning. Constructor injection supplies the matching beans, allowing `TaskServiceImpl` to depend on the `TaskRepository` interface, NOT the implementation.

Additionally, Spring Data creates the implementation of the `TaskJpaRepository` interface.

=== Mapping to JPA and saving

Sources:

* {src}/backend/infrastructure/src/main/java/nl/tijsbeek/mapper/TaskMapper.java[`backend/infrastructure/src/main/java/nl/tijsbeek/mapper/TaskMapper.java`]
* {src}/backend/infrastructure/src/main/java/nl/tijsbeek/entities/TaskJPA.java[`backend/infrastructure/src/main/java/nl/tijsbeek/entities/TaskJPA.java`]

`TaskRepositoryImpl.save` performs:

[source,java]
----
BoardStatusJPA status = task.getStatus() == null ? null :
        entityManager.getReference(
                BoardStatusJPA.class,
                task.getStatus().getId());

TaskJPA entity = TaskMapper.toJpa(task, status);
TaskJPA saved = jpaRepository.save(entity);

return TaskMapper.toDomain(saved);
----


For a column-created task, `getReference` received an entity reference for an existing status. It does not create a new status.

`TaskMapper.toJpa` copies ID, board ID, title, description, and creation time, and uses the given status reference.

[cols="1,3",options="header"]
|===
|Java member |Database mapping
|`id` |Primary key with `GenerationType.IDENTITY`
|`boardId` |Scalar `board_id`, non-null
|`title` |`title`, non-null, length 255
|`description` |`description`, non-null text
|`createdAt` |`created_at`, non-null, excluded from inserts and updates
|`status` |Lazy `ManyToOne` through column `status`
|===

PostgreSQL generates the identity ID, and Hibernate makes it available on the saved entity. Based on the received TaskJPA, a new domain Task entity is created so the original is not mutated.

=== Database-generated creation time

The schema sets:

[source,sql]
----
created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
----

The entity sets:

[source,java]
----
@Column(
    name = "created_at",
    nullable = false,
    insertable = false,
    updatable = false
)
private LocalDateTime createdAt;
----

* PostgreSQL generates a value in the row.
* Hibernate does not try to write the value to the row.

=== Transactions and failure timing

The `TaskService.createTask` and the `TaskRepository.save` method both have `@Transactional` annotated.

In this case the benefit is minimal, as this method is a single database write. In more advanced methods there is a clear benefit.

In case of a failure, within the transactions logic, all changes would be rolled back. That would result in the insert/save being reverted, and nothing being changed.

After the POST succeeds:

[source,typescript]
----
setReloadCount(current => current + 1);
----

The provider's key is:

[source,typescript]
----
const requestKey =
    `${boardId}:${selectedViewId}:${reloadCount}`;
----

Changing it makes the old result ineligible:

[source,typescript]
----
const currentResult =
    result?.requestKey === requestKey ? result : null;
----

This results in an automatic reload of the board's view.

In the backend:

. The respective `BoardView` is loaded
. All tasks, corresponding to the view are sorted and loaded from the database
. All board's statuses are loaded
. The tasks are grouped by their status
. Each task is mapped to a `TaskResponse`
. A TaskViewResponse is created and returned by the controller

In our example, this results in the following JSON:

[source,json]

        {
          "id": 42,

          "description": "Demonstrate task creation",
          "createdAt": "2026-11-17T16:30:00",

. Stores the response
. Reads all groups and sorts them by position
